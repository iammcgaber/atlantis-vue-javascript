# Agent notes

Stripped-down starter based on Atlantis v7.0.0, PrimeTek's commercial Vue 3 admin template (PrimeVue 4, Tailwind CSS v4, Vite 5). Plain JavaScript (`<script setup>`, no TypeScript), `@` → `./src`. Demo pages were removed; Dashboard, Settings, Help and an admin-only example page remain, plus the auth pages and Terms. `original_template/` (git-ignored, local only) is the untouched template, the reference for any removed demo component. `PRIMEVUE_TEMPLATE_PLAYBOOK.md` is the step-by-step guide this starter follows (ported from the Apollo starter, `Karam-Connect/apollo_template`).

## Commands

Lockfile is `package-lock.json` → npm. Node version in `.nvmrc` (exact `X.Y.Z`, RWX needs it).

- `npm run dev` — Vite dev server
- `npm run build` / `npm run preview`
- `npm run lint` — ESLint with `--fix` (vue3-essential + prettier + `@intlify/vue-i18n`, also linting the locale JSON); `npm run lint:check` doesn't fix. The scripts name their targets (`src`, `scripts` and root config files) instead of `.`, so ESLint never walks `node_modules`, `dist` or `original_template`; add new top-level code folders there.
- `npm run format` — Prettier (js/vue). Don't point `prettier --write` at `src/assets/`: vendored Atlantis styles.
- `npm test` — Vitest once; `npm run test:watch`. Single file: `npx vitest run src/stores/__tests__/layout.spec.js`; single test: add `-t "<name>"`.
- `npm run i18n:push` / `npm run i18n:pull` — sync `src/i18n/locales` with Tolgee (see i18n below).

Version pins: `@intlify/eslint-plugin-vue-i18n` v3 (v4 needs ESLint 9 flat config); `typescript` ~5.9 (several packages ask for it, and npm would otherwise resolve TypeScript 7, whose per-platform packages break `npm ci`); Vitest 3 (v4+ needs Vite 6+); `@primevue/forms` on the same version as `primevue` (forms v5 is for PrimeVue 5). After changing dependencies, check `npm ci` in a clean copy.

Tests (jsdom) live in `__tests__/` next to the code; Vitest only includes `src/**/__tests__/**/*.spec.js`. Store tests: fresh Pinia and `localStorage.clear()` per test, stop every Pinia created (`pinia._e.stop()`) so stores don't leak, `@primeuix/themes` mocked in the layout tests. Don't `structuredClone` store state (reactive proxies can't be cloned). Component tests use Vue Test Utils through `mountWithApp(component, { path, routes, props })` (`src/test/mount.js`: Pinia, vue-i18n in English, PrimeVue without a theme, a memory router at `path`; pass named routes so `RouterLink`s resolve). Use `flushPromises()` after a form submit (the Zod resolver is async). Add a regression test for each bug fixed.

## Conventions

- SFC block order (ESLint): `<script>`, `<template>`, `<style>`. Prettier: 4 spaces, single quotes, semicolons, no trailing commas, `printWidth: 250`.
- PrimeVue components are auto-imported (`unplugin-vue-components` + `PrimeVueResolver`); don't import them by hand.
- Prefer VueUse composables over hand-written listeners, timers and storage (`useMediaQuery`, `onClickOutside`, `useIntersectionObserver`, `useTimeoutFn`, `useCountdown`, `useNow` with an interval `scheduler`, `onKeyStroke`, `useStorage`); import them explicitly.
- Every user-facing string goes through vue-i18n (see i18n below); ESLint fails on raw text in templates.
- `ToastService` and `ConfirmationService` are global; one `<Toast />` lives in `AppLayout.vue`.

## Architecture

- **Routing** (`src/router/index.js`): one root route renders `layout/AppLayout.vue` with lazy app pages as children (`/`, `/settings/*`, `/help`, `/admin`, which has `meta.roles: ['admin']`). Top-level: `/auth/*` (login, register, forgot-password, reset-password, verification, access, error), `/terms` (public) and the catch-all (`views/auth/Error.vue` with `notFound`; requires auth, so signed-out users get login). `router.onError` sends failed lazy imports to the error page, imported eagerly so it can't fail the same way. `meta.breadcrumb` (array) drives the breadcrumb. The sidebar is a separate model in `layout/AppMenu.vue` (a `computed`, so items can set `visible` from the session); adding a page means updating router and menu. Hiding a menu item is cosmetic; `meta.roles` is the real check.
- **Layout**: unlike Apollo, Atlantis renders the sidebar inside the topbar (`AppTopbar.vue` → `layout-topbar-menu-section` → `AppSidebar.vue`). The topbar has the breadcrumb, the page search (`layout/PageSearch.vue`, desktop; a second instance sits in the breadcrumb bar on mobile), the avatar with a profile menu (Settings, Lock, Sign out; opened with `v-styleclass`) and the "Today" button, which opens `AppProfileSidebar.vue` (to-do list from the `todos` store and placeholder events for today). Menu modes: static, overlay, slim, slim-plus, horizontal, reveal, drawer; slim, slim-plus and horizontal open submenus as overlays on desktop. No menu themes.
- **State (Pinia)** (`src/stores/`): setup stores with HMR snippets. `layout` = `config` (preset, primary, surface, darkTheme, menuMode; persisted) + `ui` (transient menu/drawer flags) + getters and actions (`toggleMenu`, `setMenuMode(mode, path)`, `setPrimary`, `setSurface`, `setPreset`, `setDarkTheme`, `applyTheme`, `toggleProfileSidebar`). `user` = local profile; `preferences` = regional + notifications; `todos`; `lock`. Persist with `usePersistedRef(key, defaults)` (`stores/persisted.js`, on VueUse `useStorage`): key `app.<key>`, objects shallow-merged over defaults, malformed values ignored, storage errors swallowed, and changes from other tabs picked up (the layout store re-applies the theme when they arrive). Access fields on the store object; don't destructure without `storeToRefs`. `AppLayout.vue` maps `config`/`ui` to `layout-*` classes.
- **Auth** (`src/auth/`): Better Auth client only (`better-auth/vue` + `emailOTPClient()`). Without `VITE_AUTH_URL` (`.env.example`), `mock-server.js` answers the endpoints the app uses with real response shapes: any password and any 6-digit code work, `admin@…` users get `role: 'admin'`, users and session live in localStorage (`app.auth.mock`, never passwords), and reset links and codes are logged to the console. A real server needs `emailAndPassword`, `emailOTP`, `user.deleteUser.enabled` and the admin plugin for roles. `router/guard.js` reads meta through matched records (children inherit): `requiresAuth` → login with `?redirect=`; `guestOnly` → home; `roles` → access denied with `?from=`; while locked, in-app navigation is blocked. `safeRedirect()` allows only same-app paths. Register → Verification (email OTP) → redirect. Sign out with `useSignOut()`, which also clears the lock. Auth pages use `components/auth/AuthLayout.vue` (Atlantis illustration on the left, picked with `image`: login, register, forgot-password, newpassword, verification, lock); error/access/not found use `components/auth/StatusPage.vue`. Zod schemas in `auth/schemas.js`. In Zod 4, avoid `z.literal()` in a schema with a cross-field `.superRefine()`.
- **Page search** (`src/search/`): Fuse.js fuzzy search over routes with `meta.search: { icon, keywords, title? }`; the title defaults to the breadcrumb. `buildPageIndex`/`searchPages` are pure and tested, `usePageSearch` wraps VueUse `useFuse`, and pages whose `meta.roles` exclude the user are left out. Give new pages a `search` entry. `PageSearch.vue` keeps Atlantis's expanding field (an icon button that opens into a PrimeVue `AutoComplete`); the field is `visibility: hidden` until its transition starts, so focus is set after a short delay.
- **Feature flags (Flagsmith)** (`src/flags/index.js`, `flagsmith-vue`): `installFlags(app)` in `main.js`; read flags with `useFlags(['name'])`. Every flag goes in `DEFAULT_FLAGS` (published right away; the SDK only emits after a fetch). Without `VITE_FLAGSMITH_ENVIRONMENT_ID` nothing is fetched. `App.vue` identifies the user by id with the role as a trait, again when either changes, and logs out of Flagsmith on sign-out. Example: `profile_photo_upload` gates Settings > Profile > Photo.
- **i18n** (vue-i18n 11, Composition API, `src/i18n/`): `$t` in templates, `const { t } = useI18n()` in scripts (option lists in a `computed`), `<i18n-t>` for sentences with markup. Prefer literal `t('a.b')` calls: the linter can't follow keys built from strings. ESLint (`@intlify/vue-i18n`): `no-raw-text` (including text attributes such as label, placeholder, header, aria-label, alt; it doesn't look inside `<script>`), `no-missing-keys`, `no-unused-keys` (ignoring `nav.*`, `validation.*`, `auth.errors.*`, which are referenced indirectly) and camelCase keys. Brand names and placeholder data live in script constants. Languages are in `LOCALES` (each with its primelocale file for PrimeVue's own texts); messages in `locales/<code>.json` (en, es, fr, de, pt, ar, ar-DZ, ar-SY, bn, hi, zh). Add a key to every full language (`i18n.spec.js` fails otherwise); regional variants only hold overrides and fall back to their base language. English is bundled; `setLocale(code)` loads the rest on demand and ignores superseded calls. Zod schemas hold message keys shown by `components/forms/FieldError.vue`; Better Auth errors go through `authErrorMessage` (`auth/errors.js`). Numbers use named formats (`$n(v, 'currency' | 'currencyWhole' | 'integer' | 'percent' | 'percentWhole')`); dates, month and country names use `Intl` with `locale.value`, and charts rebuild their labels. vue-i18n treats `{ } @ $ |` as special, so pass emails and code as params. Arabic sets `<html dir="rtl">`: use logical Tailwind classes (`ms-`/`me-`, `ps-`/`pe-`, `start-`/`end-`, `text-start`/`text-end`) and `margin-inline` in layout SCSS; the sidebar stays on the left. All non-English texts are drafts by Claude and need native-speaker review.
- **Tolgee**: the locale files in git are the source of truth; Tolgee is where they get reviewed, with vue-i18n still the runtime (`@tolgee/vue` isn't used). `npm run i18n:push` uploads (`.tolgeerc.json`: `JSON_ICU`, `forceMode: KEEP`, explicit languages) and `npm run i18n:pull` downloads and formats; `scripts/tolgee.mjs` passes `VITE_APP_TOLGEE_API_URL`/`VITE_APP_TOLGEE_API_KEY` from `.env`. In `npm run dev` with the key set, `src/i18n/tolgee.js` adds Alt+click in-context editing; it is loaded only when `import.meta.env.DEV` and the mode isn't `test`, so builds contain neither Tolgee nor the key (check `dist/` if that changes). In dev, translated strings carry invisible marker characters, so never compare translated strings in code. Production layers the Tolgee CDN (`VITE_TOLGEE_CDN_URL`, flat JSON converted by `i18n/messages.js`) over the bundled messages, in the background and once per language. New languages must be created in the Tolgee UI first. There is no Tolgee project for Atlantis yet.
- **Lock screen** (`stores/lock.js` + `layout/AppLockScreen.vue`, mounted in `App.vue`): an overlay, so the page underneath keeps its state; the app is `inert` while it shows. The lock persists. Unlock re-runs `signIn.email`, because Better Auth's `/verify-password` is server-only.
- **File uploads (Filestack)** (`src/service/filestack.js`): `filestack-js` loads with a dynamic `import()` (own ~580 kB chunk). Key from `VITE_FILESTACK_API_KEY`, falling back to Filestack's shared demo key; never hardcode a real key. The demo key's uploads can be blocked (`429`), so test with your own key and localhost in its allowed origins. `openAvatarPicker` forces a square crop; `avatarUrl(handle)` resizes before output. Settings > Profile > Photo saves to the auth user's `image` right away. `useAvatar()` gives the topbar its image (placeholder `/demo/images/pages/avatar.png`). Upload retries are kept low and a failed upload closes the picker.
- **Theming** (`src/layout/theme.js`): presets Aura and Lara, primary and surface palettes. Presets load on demand (`loadPreset`, unknown names → Aura); `main.js` installs Pinia, loads the saved preset, boots PrimeVue with it and awaits `layout.applyTheme()` before mounting. Theme changes go through layout store actions. `layout/AppConfig.vue` is the inline Appearance panel (Settings > Appearance). Dark mode is the default: `app-dark` on `<html>` (also set in `index.html` to avoid a flash), matching `darkModeSelector` and the Tailwind `dark` variant.
- **Styling**: `src/assets/` holds the Atlantis styles (originally the private `primefaces/atlantis-assets` submodule, now plain files). Layout SCSS in `assets/layout/` (by sidebar mode, light/dark variables; padding in `_content.scss`, `$content-max-width` 1730px in `_sass_variables.scss`). Tailwind v4 is CSS-first in `assets/tailwind.css` (breakpoints sm 576 / md 768 / lg 992 / xl 1200 / 2xl 1920, `tailwindcss-primeui`) and only scans `index.html` and `src` (`source(none)` + `@source`), so class names used elsewhere aren't generated. Auth and status page images are in `public/demo/images/pages/`.
- **Accessibility** (target WCAG 2.2 AA): the app layout has a skip link (`.skip-link`, first in the tab order) to `<main id="main-content">`, a `<header>` topbar and the sidebar as the labelled `<nav>`. After moving to another page (a different `route.matched[1]`), focus goes to `<main>`; moving between sections of one page (Settings tabs) keeps it. Escape closes the menu where it covers the page (`layout.closeMenuOverlay()`) and returns focus to the menu button. The topbar's account menu is a disclosure (button with `aria-expanded` + a list of links and buttons, Escape and outside clicks close it), not `v-styleclass` on a link. Browser titles come from `router/title.js`: `meta.title` (one key) or the breadcrumb, most specific first, "· Atlantis" at the end, translated; give new top-level routes a `breadcrumb` or `title`. One `<h1>` per page (`sr-only` when the breadcrumb already shows the name, like the Dashboard); card titles are `<h2>`. Status pages put both lines in one `<h1>`. Icon-only buttons and links need a translated `aria-label` (layout controls under `a11y.*`); decorative images get `alt=""`. Wrap every PrimeVue `<Password>`'s `inputProps` in `passwordInputProps()` (`components/forms/password.js`). The verification code renders `InputOtp`'s inputs through its default slot only to label each digit. Never use `outline: none` without a `:focus-visible` replacement: the layout's links and buttons, and each menu mode's menu links (`assets/layout/sidebar/*.scss`), use the PrimeVue focus-ring tokens. Contrast: in light mode the primary colour is each palette's lightest shade with 4.5:1 against white and the page background (`accessibleShade` in `layout/theme.js`: 700 for most, 600 for blue/indigo/violet/purple, 800 for yellow), hover/active one and two shades darker; `accessibleComponents` moves severity buttons, unselected SelectButton labels and dark-mode messages to passing shades; `theme.spec.js` checks every palette. Coloured text uses 700 shades in light mode and 400s in dark (`text-cyan-700 dark:text-cyan-400`); status-page headings use 600/700 (light) and 400/500 (dark), which pass 3:1 for large text. Links inside text are underlined (`underline!`). Appearance swatches are 32px buttons with `aria-pressed`. axe can't measure contrast over Atlantis's background image (it reports "incomplete"), so compute ratios for new colours. Check pages with axe and the keyboard before shipping.
- **Phone field**: `components/forms/PhoneInput.vue` wraps vue-tel-input, styled with PrimeVue's global `--p-form-field-*` / `--p-overlay-select-*` tokens (component tokens like `--p-select-*` only exist when that component is on the page). Its v-model is E.164; it's bound with `<FormField v-slot="$field" name="phone">` + `$field.onInput({ value })` and validated with libphonenumber-js. Country names come from `Intl.DisplayNames`.
- **Settings** (`views/settings/`): `SettingsLayout.vue` (left nav, tab strip below `lg`) + one child route per section; `/settings` redirects to profile. Built from `components/settings/SettingsSection.vue` and `SettingsRow.vue`. Profile uses PrimeVue Forms + Zod (`profile-schema.js`; validates on blur and submit). Every form field must be in the schema, because the resolver submits the parsed output and `z.object()` strips unknown keys. Change password (`password-schema.js`) validates on mount and on input, disables submit until valid and shows errors only for dirty fields. Deleting the account needs the typed phrase `DELETE`. Profile and Preferences save on Save; Notifications and Appearance apply immediately.
- **Views**: `Dashboard.vue` composes five widgets from `components/dashboard-widgets/` (Chart.js via PrimeVue `Chart`, hardcoded data). No backend: auth is mocked and everything else is in Pinia + localStorage.

## CI

RWX, `.rwx/claude-atlantis-vue.yml` at the repository root: on pull requests and pushes to `main`, `npm ci` (cached until `package.json`/`package-lock.json` change), then lint (ESLint problems annotated), test (Vitest JSON report in `tmp/vitest.json`, so failures show inline; needs `includeTaskLocation`) and build in parallel. Tasks filter to this folder, so changes elsewhere are cache hits. A new push cancels the PR's running CI. `rwx run` uploads local changes as a diff limited to 5 MB, so large changes need pushing first.

## Deployment

DigitalOcean App Platform static site, defined in `.do/app.yaml` (validate with `doctl apps spec validate .do/app.yaml`; create with `doctl apps create --spec .do/app.yaml`). It builds `source_dir: claude/atlantis-vue` from `main` on every push (App Platform's GitHub integration needs access to the private repo): the Node.js buildpack runs `npm ci` with the Node version from `package.json` `engines` (keep it on the `.nvmrc` major), then `npm run build`, and serves `dist/`. The router uses history mode, so `catchall_document: index.html` is required; without it deep links and reloads return 404. Build-time `VITE_*` variables go in the spec's `envs` with scope `BUILD_TIME` (commented examples there); they end up in the public bundle, so never add the dev-only `VITE_APP_TOLGEE_*` credentials.
